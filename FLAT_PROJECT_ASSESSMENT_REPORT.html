1. STATE DIAGRAM
1.1 Introduction

A Deterministic Finite Automaton (DFA) is used in the Online Food Ordering and Delivery Tracking System project to model, govern, and strictly validate the complete lifecycle of customer orders. In commercial food delivery applications, orders must strictly follow an operational sequence: from initial order placement, kitchen staff confirmation, cooking preparation, packaging, dispatch via courier, to final delivery handover.

The automaton starts from the initial state S0 (Order Created). Whenever authorized actors (customer, kitchen manager, delivery partner) submit an action, the DFA evaluates the transition function δ(state, action). If the action is legally defined for the current state, the DFA advances deterministically to the next state. If an undefined action or illegal state jump is attempted (e.g., trying to dispatch food before cooking, or cancelling food after preparation has commenced), the transition is strictly rejected with mathematical proof. When the order reaches S5 (Delivered) or S6 (Cancelled), it enters a final/accepting state with zero outgoing transitions, guaranteeing that completed orders cannot be altered.

1.4 Formal Definition of DFA

A Deterministic Finite Automaton is mathematically defined as a 5-tuple:

M = (Q, Σ, δ, q0, F)

Where:

  • Q: Finite set of states = {S0, S1, S2, S3, S4, S5, S6}
  • Σ: Finite set of input alphabet symbols = {confirm, start_preparation, food_ready, dispatch, deliver, cancel}
  • δ: State transition function δ: Q × Σ → Q (Partial Function mapping current state and input to unique next state)
  • q0: Initial state = S0 (Order Created)
  • F: Set of final / accepting states = {S5, S6} (S5 = Delivered, S6 = Cancelled)

Language Accepted by the Automaton L(M):
The DFA accepts any valid sequence of symbols w ∈ Σ* that drives the automaton from q0 into an accepting state in F.

L(M) = {
    "confirm · start_preparation · food_ready · dispatch · deliver",
    "cancel",
    "confirm · cancel"
}

Current State (q) Input Condition (σ) Next State (δ) Formal Transition Proof & Description
S0 confirm S1 δ(S0, confirm) = S1 (Order accepted into kitchen queue)
S0 cancel S6 δ(S0, cancel) = S6 (Order cancelled by user or rejected)
S1 start_preparation S2 δ(S1, start_preparation) = S2 (Chef initiates ingredient preparation)
S1 cancel S6 δ(S1, cancel) = S6 (Cancelled before cooking commences)
S2 food_ready S3 δ(S2, food_ready) = S3 (Cooking completed, packaging done)
S3 dispatch S4 δ(S3, dispatch) = S4 (Delivery partner assigned & picked up)
S4 deliver S5 δ(S4, deliver) = S5 (Food delivered to customer, order fulfilled)
S5 Any σ ∈ Σ ∅ (REJECT) δ(S5, σ) is undefined; Terminal state, immutable record
S6 Any σ ∈ Σ ∅ (REJECT) δ(S6, σ) is undefined; Terminal state, cancelled permanently

Special Conditions & Mathematical Invariants:

  • Partial Function Enforcement: In formal automata theory, δ is a partial function. Any transition not explicitly listed in the table (e.g., δ(S0, dispatch) or δ(S2, cancel)) is undefined (∅). In the Express backend, undefined transitions evaluate to false and return an HTTP 422 Unprocessable Entity response.
  • Irreversibility of Preparation: Once the automaton enters state S2, the cancel symbol is undefined (δ(S2, cancel) = ∅). This mathematically prevents customers from aborting orders once food preparation has started.
  • Terminal State Immutability: The accepting states F = {S5, S6} have zero outgoing transitions. Once an order reaches S5 or S6, no subsequent operations can alter its state.

/**
 * Formal Languages and Automata Theory (FLAT) Module
 * Deterministic Finite Automaton (DFA) for Food Order Lifecycle
 *
 * Mathematical 5-Tuple Definition:
 * M = (Q, Sigma, delta, q0, F)
 */

export const STATES = Object.freeze({
  S0: 'Order Created',
  S1: 'Order Confirmed',
  S2: 'Food Preparation Started',
  S3: 'Food Prepared',
  S4: 'Out for Delivery',
  S5: 'Delivered',
  S6: 'Cancelled'
});

export const INITIAL_STATE = 'S0';
export const FINAL_STATES = Object.freeze(['S5', 'S6']);

export const ALPHABET = Object.freeze([
  'confirm',
  'start_preparation',
  'food_ready',
  'dispatch',
  'deliver',
  'cancel'
]);

/**
 * State Transition Table delta: Q x Sigma -> Q (Partial Function)
 */
export const TRANSITIONS = Object.freeze({
  S0: Object.freeze({ confirm: 'S1', cancel: 'S6' }),
  S1: Object.freeze({ start_preparation: 'S2', cancel: 'S6' }),
  S2: Object.freeze({ food_ready: 'S3' }),
  S3: Object.freeze({ dispatch: 'S4' }),
  S4: Object.freeze({ deliver: 'S5' }),
  S5: Object.freeze({}),
  S6: Object.freeze({})
});

export function isFinalState(state) {
  return FINAL_STATES.includes(state);
}

export function getValidActions(state) {
  const transitionsFromState = TRANSITIONS[state];
  return transitionsFromState ? Object.keys(transitionsFromState) : [];
}

/**
 * Executes DFA transition: delta(currentState, input) -> nextState
 */
export function transition(currentState, input) {
  // 1. Verify currentState in Q
  if (!STATES[currentState]) {
    return {
      valid: false,
      currentState,
      input,
      error: `Invalid DFA state: "${currentState}". State must belong to Q.`,
      allowedActions: []
    };
  }

  // 2. Verify input in Sigma
  if (!ALPHABET.includes(input)) {
    return {
      valid: false,
      currentState,
      input,
      error: `Invalid input symbol: "${input}". Must belong to alphabet Sigma.`,
      allowedActions: getValidActions(currentState)
    };
  }

  // 3. Final State Check: No outgoing transitions permitted from F
  if (isFinalState(currentState)) {
    return {
      valid: false,
      currentState,
      input,
      error: `Cannot transition from final state "${currentState}". Terminal states in F have no outgoing transitions.`,
      allowedActions: [],
      formalExplanation: `delta(${currentState}, ${input}) is undefined because ${currentState} in F.`
    };
  }

  // 4. Lookup next state in delta
  const nextState = TRANSITIONS[currentState]?.[input];
  if (!nextState) {
    const valid = getValidActions(currentState);
    return {
      valid: false,
      currentState,
      input,
      error: `Transition delta(${currentState}, "${input}") is undefined. Allowed action(s): ${valid.join(' or ')}.`,
      allowedActions: valid,
      formalExplanation: `In DFA M, delta(${currentState}, ${input}) -> null. Undefined transition rejected to prevent illegal state jump.`
    };
  }

  // 5. Valid Deterministic Transition
  return {
    valid: true,
    currentState,
    input,
    nextState,
    label: STATES[nextState],
    isFinal: isFinalState(nextState),
    formalExplanation: `delta(${currentState}, ${input}) = ${nextState} (${STATES[nextState]})`
  };
}

/**
 * Simulates a full string sequence w in Sigma*
 */
export function simulateString(inputSequence = []) {
  let state = INITIAL_STATE;
  const trace = [];

  for (let i = 0; i < inputSequence.length; i++) {
    const sym = inputSequence[i];
    const res = transition(state, sym);
    if (!res.valid) {
      trace.push({ step: i + 1, from: state, input: sym, to: null, valid: false, error: res.error });
      return { accepted: false, trace, finalState: state, reason: `DFA crashed at step ${i + 1} on "${sym}".` };
    }
    trace.push({ step: i + 1, from: state, input: sym, to: res.nextState, valid: true, label: res.label });
    state = res.nextState;
  }

  const accepted = isFinalState(state);
  return {
    accepted,
    trace,
    finalState: state,
    reason: accepted
      ? `String accepted! Automaton halted in final state ${state} (${STATES[state]}).`
      : `String halted in non-final state ${state} (${STATES[state]}). Not in L(M).`
  };
}

ADVANTAGES OF USING FLAT CONCEPT IN ONLINE FOOD ORDERING AND DELIVERY TRACKING SYSTEM
  • Deterministic State Progression: The DFA mathematically guarantees that an order can only advance along rigorously defined operational pathways, ensuring predictable, reproducible system behaviour.
  • Mathematical Prevention of State-Skipping: Eliminates race conditions and fraudulent API manipulation. An order cannot jump directly from "Created" to "Delivered" without traversing cooking, packaging, and courier dispatch.
  • Zero Food Wastage Protection: By defining δ(S2, cancel) = ∅, the automaton mathematically locks cancellation once preparation starts, safeguarding restaurants against financial loss.
  • Terminal State Immutability: The formal definition of final states F = {S5, S6} with no outgoing transitions guarantees that fulfilled or cancelled orders can never be modified or tampered with.
  • Decoupled Formal Business Logic: Encapsulates the entire workflow rules into a clean mathematical 5-tuple M = (Q, Σ, δ, q0, F) independent of UI or database layers, enabling automated verification and 100% test coverage.
